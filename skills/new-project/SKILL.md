# 新项目立项

用户有新想法时按以下流程走，全程用 `ask_user_question` 工具提问，不要一次性铺长文。

## 第 0 步：读记忆

先读本 skill 目录下的 `memory.json`：
- `paths`：历史 clone 路径（最多保留 2 个，最新使用的放前面）
- 取最近使用的路径作为本次默认推荐项。

## 第 1 步：起名推荐

1. 根据用户的想法和身份（开发者、macOS/iOS 生态、独立项目风格），提出 **3 个候选项目名**，每个包含：
   - **英文项目名**（仓库名，适合做 CLI/产品名）
   - **中文名称**（产品中文名）
2. **查重是硬要求**，每个候选名都要验证：
   - `gh search repos <名字> --limit 10` 查 GitHub 是否已有同名或近似仓库
   - 必要时 web_search 查是否已有同类产品使用该名字
   - 有明显重名或知名同类产品占用 → 换名，不推荐给用户
   - 在候选列表里注明查重结果（如「GitHub 无同名」）
3. 用户可从候选中选，也可自己起名；用户自起的名字也顺手查重并告知结果。
4. **项目名是硬前置**：只有用户明确选定某个候选名或给出自己起的名字，才算项目名已确定。用户跳过该问题、表示不满意、说「继续推荐」「再想想」等，一律理解为**要新的一批候选名**——换风格再提 3 个并同样查重，**绝不许自行挑一个当作已确定的名字继续往下走**。
5. 每批候选的命名风格（如音译、寓意、产品定位词）要和上一批明显不同，并问用户偏好的方向，避免反复出同类名字。

## 第 2 步：仓库可见性

问：**公有（public）还是私有（private）？** 二选一。

## 第 3 步：clone 路径

1. 从 `memory.json` 的 `paths` 里列出已记住的路径作为选项（推荐项放第一个，标「(Recommended)」）。
2. 用户选了 → 直接用。
3. 用户没选 → 让用户输入新路径；输入后**写入 `memory.json`**（新路径放最前，`paths` 超过 2 个就删掉最旧的）。

## 第 4 步：执行

**前置条件：第 1 步的项目名已由用户明确确定。未确定时禁止执行本步（不许建仓库）。**

```bash
cd <选定路径>
gh repo create <项目名> --<public|private> --clone
```

完成后汇报：仓库地址、本地路径。

## 第 5 步：创建初始 README（必做）

clone 完成后立即在仓库根目录创建 `README.md`，内容包含：
1. **项目中文名**（一级标题，附英文名/仓库名）
2. **简介**：这个项目要做什么（根据用户立项时描述的想法，1-3 句）
3. 不写密钥、不写真实 URL

写完后 commit 并推送：
```bash
cd <本地路径>
git add README.md && git commit -m "docs: add README" && git push -u origin main
```
（推前遵守敏感信息检查约定；仓库刚建、无历史风险。）

然后问一句是否现在开始搭项目骨架。

## 记忆维护

- 每次成功选路径后立即更新 `memory.json`，格式：
```json
{ "paths": ["/Users/czm/githubProject"], "history": [{"name": "OmniSpeakIME", "date": "2026-11-12"}] }
```
- `history` 只保留最近 10 条，供下次参考用户命名风格。
