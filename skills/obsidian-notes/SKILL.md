## 核心操作模式

### 模式 1：摘抄模式（原封不动复制）⚠️ 优先识别

**触发词**：
- "摘抄"
- "直接摘抄"
- "原封不动"
- "不要改动"
- "直接复制"
- "复制粘贴"

**行为规则**：
1. **禁止修改内容**：不做任何总结、精简、重新组织
2. **完整复制**：将之前生成的内容原封不动地复制到笔记
3. **保留格式**：保持原有的 Markdown 格式、代码块、表格等
4. **仅添加 Meta**：只在开头添加必要的 Meta 信息（日期、分类、标签）

**摘抄模式的笔记格式**：
```markdown
# [根据内容自动生成标题]

## Meta
- **Created**: YYYY-MM-DD
- **Category**: [自动识别分类]
- **Tags**: #标签1 #标签2
- **Mode**: 摘抄

## 内容

[原封不动复制的内容，不做任何修改]
```

**示例**：
- 用户说："摘抄，直接摘抄你刚刚生成的内容"
- 执行：找到上一条 AI 生成的完整内容，原封不动复制到笔记文件

### 模式 2：业务流程整理模式

**触发词**：
- "整理下这个业务流程"
- "整理一下这个业务流程"
- "把这个业务流程整理到知识库"

**目标**：维护持续更新的业务知识，不重复生成一次性问题总结。

**核心规则**：
1. 写入前必须搜索目标知识库的文件名和正文。
2. 已存在同主题文档时，优先修改现有文档，不重复新建同类总结。
3. 业务来源或流程变化时，更新“当前流程”，同时在“演进时间线”追加带日期的历史记录；不能用新逻辑覆盖旧历史。
4. 没有相关文档时，才创建最小必要的文档集合。
5. 允许拆分多篇笔记，并用 Obsidian `[[双链]]` 连接；不要强制全部写进一篇。
6. 代码路径、行号和实现类名属于易变证据，统一放在文档末尾并标注复核日期。

**标准工作流**：
1. 提取产品、模块、接口、字段、数据实体、权限主体和核心业务词。
2. 优先使用用户指定目录；否则按自动分类规则确定知识库范围。
3. 用 `rg --files` 搜索相似文件名，再用 `rg` 搜索接口名、字段名、实体名、业务同义词和代码标识。
4. 阅读所有直接相关笔记后判断处理方式：
   - 已有当前流程文档：更新当前来源、链路、优先级和 `Last reviewed`。
   - 已有时间线：只追加新的生效日期、变化前后和证据，不删除旧节点。
   - 已有案例文档：更新状态，并链接当前流程和时间线。
   - 存在零散重复笔记：合并到事实最完整的主文档，避免继续扩散。
   - 完全不存在：按需创建索引、当前流程、演进时间线、案例中的最小集合。
5. 优先说明数据从哪里来、经过什么路径、由谁决定、何时变化、变化前后有什么不同。
6. 使用完整文字和 Mermaid 同时说明流程。
7. 将易变代码索引放在最后，注明分支、环境、生效时间或复核日期。
8. 写入后再次搜索同主题文件，检查是否产生重复，并校验所有 `[[双链]]` 指向存在的笔记。

**推荐结构**（按复杂度选用）：

```text
主题索引
├── 当前数据来源/业务流程
├── 按日期维护的演进时间线
└── 具体问题或变更案例
```

**内容口径**：
- 当前流程只描述最近确认的生效逻辑，并写明复核日期。
- 时间线保留每个历史阶段的来源、组装方式、空值语义、生效日期和证据。
- 案例说明现象如何由业务链路产生，不替代主流程文档。
- 无法确认生效时间时标记“待确认”，不得猜测日期。
- 区分已提交代码、未提交改动、环境配置和计划方案，不能混写成已生效事实。

## 操作流程

### 摘抄模式流程

1. **识别触发词**：检测到"摘抄"、"原封不动"等关键词
2. **定位内容**：找到上一条 AI 生成的完整内容
3. **分类识别**：根据内容关键词确定文件夹和标签
4. **生成文件名**：`YYYYMMDD-[内容标题].md`
5. **写入文件**：
   - 添加 Meta 信息（日期、分类、标签、Mode: 摘抄）
   - **原封不动**复制内容，不做任何修改
6. **确认保存**：告知用户文件路径

### 整理模式流程

1. **确认内容**：明确要保存的内容
2. **分类识别**：确定项目/主题/根目录
3. **内容整理**：可以总结、精简、重新组织
4. **生成文件**：包含完整 Meta 和摘要
5. **确认保存**：告知用户文件路径

### 业务流程整理模式流程

1. 根据主题关键词搜索已有笔记
2. 阅读相关笔记，识别当前流程、历史时间线和案例文档
3. 已存在则原位更新；不存在才新建
4. 更新当前来源，并按日期追加流程变化历史
5. 用双链连接拆分后的笔记
6. 将代码位置放在最后并标注为易变信息
7. 再次查重并校验双链
8. 告知用户更新了哪些旧文档、创建了哪些新文档

### 搜索模式流程

1. 使用 grep 搜索 vault 内容
2. 返回匹配的笔记及摘要
3. 显示文件路径

```bash
# 按标签搜索
grep -r "#标签名" /Users/czm/Documents/czm-obisidian/ --include="*.md"

# 列出某分类下所有笔记
ls -la /Users/czm/Documents/czm-obisidian/[Category]/

find /Users/czm/Documents/czm-obisidian/ -name "*.md" -mtime -7
```

## 注意事项

- 写入前检查目录是否存在，不存在则创建
- 使用绝对路径 `/Users/czm/Documents/czm-obisidian/`
- 文件名避免特殊字符，中文可以使用
- 保存成功后告知用户文件位置
- **摘抄模式下严禁修改内容**，这是用户的明确要求
- **业务流程整理模式必须先查重，存在则更新，不存在才新建**
- 不要为了记录一次新问题就重复创建相同主题的流程总结
- 流程变化时保留历史，通过时间线追加新节点，保证知识库既最新又可追溯
