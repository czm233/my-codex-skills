# 引导式探索

## 0. 调用即入口（最高优先级，先看这条）

**本 skill 被显式调用时，一律直接进入「需求引导模式」。**

判定顺序，自上而下，命中即停：

1. 用户消息以 `/guided-exploration` 开头（斜杠调用）→ **引导模式**
2. 本文件是通过 `skill` 工具载入的（不是用户随手提到的）→ **引导模式**
3. 用户说「用引导式探索」「帮我理清思路」「先问清楚再做」「必须要问」→ **引导模式**
4. 用户在描述一个"要做一个东西"的需求（不是提问）→ **引导模式**
5. 以上都不中（纯提问、没有要你做东西）→ 问答模式

显式调用 = 用户已经点名要这套提问流程。此时**不允许**：

- 降级成问答模式
- 把"这次该不该问"留给模型自行判断
- 拿"需求已经很详细""用户说快速做个原型"当跳过提问的理由

> 唯一例外：用户在同一条消息里明确说「别问了，直接做」，此时跳过提问、直接执行。

## 1. 需求引导模式

### 开始之前：禁止自作主张

在提问得到回答前**禁止**：

- 调用 `create_goal`（会触发自动续轮，把"先问"覆盖成"继续做"）
- 写文件、建目录、装依赖、起服务
- 把用户明确说"没想好"的点自行拍板（例如替用户定 2D/3D、尺寸、格式、帧数）
- 用文字代替提问——在回复正文里写"你可能还想问"不算提问

### 提问方式

- **必须使用 `ask_user_question` 工具**（能点选、能阻塞），不在正文里写问题
- **每轮只问一个问题**；一次回复默认 1 个，硬上限 3 个
- 问题要具体、可直接回答；不评价用户的回答，不给建议
- 优先级：先问用户**自己点明没想好**的点 → 再问影响后续实现的关键分叉 → 最后问细节
- 每轮问完就停下来等回答，不自行补全、不并行推进其他工作

### 四个方向轮着来

1. **澄清**：你到底想要什么？
2. **前提**：你的判断基于什么？
3. **证据**：反过来会怎样？
4. **后果**：做了之后呢？

（有具体技术分叉时，用澄清方向问分叉，比套模板更有效。）

### 什么时候可以开始执行

- 用户回答了关键分叉问题，或明确表示「按你定的来」「先做起来再说」
- 此时才允许 `create_goal` / 写代码 / 起服务；动手前先把"已确认的点 + 仍默认的假设"用表格列出来给用户看一眼

### 退出

- 用户说「直接告诉我吧」→ 退出引导，给结论
- 用户说「差不多了」→ 总结聊出来的东西
- 用户说「别问了，直接做」→ 立即停止提问，开始执行

## 2. 问答模式（仅限纯提问）

只在第 0 节五条全部不命中时使用：用户只是问一个问题，没有要你做东西。

### 回答原则

- **图优先**：流程、时序、结构、对比 → 用 Mermaid 图表或表格，不用大段文字
- **精准作答**：只答所问，不主动拓展背景、原理、替代方案
- **结论先行**：第一句就是答案

### 回答后

提供 2-3 个你可能想追问的方向（可选，不问不推）：

> 你可能还想问：
> - ...
> - ...
