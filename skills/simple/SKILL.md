# Simple

把目标内容换一种更容易理解的方式重新讲清楚，不只是压缩或重复原文。

## 确定解释对象

1. 优先解释用户明确指定的内容。
2. 用户只说“看不懂”或直接调用本 Skill 时，解释紧邻的上一条回答，不要求用户重复粘贴。
3. 仅在上下文中确实无法确定目标时，询问一个简短问题。

## 重组内容

1. 先用一句话说明结论或整体作用。
2. 用通俗中文完整解释背景、参与者、输入、关键步骤、判断分支、输出和异常情况。
3. 技术术语首次出现时，先写通俗含义，再在括号中保留原术语。
4. 保持原内容的事实、条件和结论；不要为了简化而遗漏关键限制，也不要补造不存在的调用或业务规则。
5. 将长句拆短，一段只表达一个重点。优先使用具体主语，避免连续使用“它”“这个”等模糊指代。

## 默认输出结构

除非用户明确要求更少的形式，否则按以下顺序全部输出。

### 一句话先懂

用一到三句话给出最核心的结论，让用户先建立整体认识。

### 完整文字说明

按实际执行顺序或因果关系讲解。说明“谁在什么条件下，拿什么输入，做什么，得到什么结果”。文字说明必须能够独立读懂，不能只让用户看图。

### 流程图

使用 Mermaid `flowchart`。必须包含清晰的开始、主要步骤、判断分支和结果；不存在判断时不要强行添加。节点文字使用通俗短句。

### 时序图

使用 Mermaid `sequenceDiagram`。参与者使用真实角色、模块或系统，消息按发生顺序排列，并标出关键返回结果、条件分支或失败路径。

如果目标内容没有真实参与者或时间交互，仍提供时序图，但将标题明确写成“理解顺序（不是实际系统调用）”，只展示推荐的理解顺序，避免让用户误以为这是实际调用链路。

### 对照表

用 Markdown 表格汇总最需要比较或核对的信息。根据内容选择列，优先考虑：

| 对象/步骤 | 谁负责 | 输入或前提 | 做什么 | 输出或结果 | 容易误解的点 |
|---|---|---|---|---|---|

不要机械保留空列；静态概念可改用“概念、通俗解释、作用、例子”的列结构。

### 一句话记忆

用一句便于复述的话收尾，帮助用户确认自己是否理解。

## 图表质量要求

- 让文字、流程图、时序图和表格相互补充，不要四次逐字重复同一内容。
- 保持图的范围与原说明一致；信息很多时先画主链路，再在文字中补充细节。
- Mermaid 节点或参与者含空格、括号、标点时使用引号或安全别名，避免渲染失败。
- 流程图负责表达步骤与分支，时序图负责表达参与者之间随时间发生的交互，表格负责对照差异与职责。
- 对无法从上下文确认的信息明确标注“未知”或“需确认”，不要猜测。
