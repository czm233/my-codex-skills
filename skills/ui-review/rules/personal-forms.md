# 表单信息层级与多阶段任务

以下为个人基线，不计功能分。来自 React、TypeScript 与 CSS 表单案例；不依赖框架特定版本。用户明确了偏好，最终视觉验收尚未确认，记录不代表页面已通过验收。

## UI-BASELINE-010 辅助说明与表单正文保持清晰层级
- 类型：个人基线
- 状态：已确认（偏好；最终视觉待确认）
- 适用条件：有字段、输入控件和辅助说明的表单；不限框架版本。
- 现象：说明段落与字段字号、颜色相近，穿插后难以区分提示与填写内容。
- 检查方法：比对标签、正文和提示的计算样式与位置；另查关键错误及必填条件没有被一起弱化。
- 通过标准：普通说明使用较小字号、仍可读的次级颜色，邻近所属字段或操作；关键错误保持清晰。
- 严重程度与权重：个人基线，不计功能分。
- 原因：源码混用普通段落与未统一的提示样式。
- 解决办法：案例统一提示为12px与现有次级色；具体字号须遵循各项目规范，不把12px当通用要求。
- 来源与日期：用户反馈、源码与实测，2026-10-05。
- 验证记录：浏览器计算样式确认12px与次级色，构建与回归通过；完整对比度、缩放、深色主题及最终人工视觉未验收。

## UI-BASELINE-011 图片加工与对比区域独立分组
- 类型：个人基线
- 状态：已确认（偏好；最终视觉待确认）
- 适用条件：表单包含原图、加工结果、尺寸和操作，另有文案等字段；不限框架版本。
- 现象：图片处理与文案流式混排，区域归属难辨。
- 检查方法：检查分组标题、可见边界和语义；原图、结果、尺寸及图片操作应在组内，其他字段在组外。
- 通过标准：图片处理范围明确，原图和结果分别标识，后续字段不混入图片分组。
- 严重程度与权重：个人基线，不计功能分。
- 原因：图片比较组件与文案字段相邻，缺少独立处理容器。
- 解决办法：案例增加带标题、边框、浅底色的语义分组，保留原图与结果比较；不要求其他项目固定双列。
- 来源与日期：用户反馈、源码与实测，2026-10-05。
- 验证记录：浏览器确认分组边框与两图展示，回归覆盖图片切换与预览接受；窄屏、辅助技术及最终人工视觉未专项验收。

## UI-BASELINE-012 轻量保存成功反馈紧邻按钮
- 类型：个人基线
- 状态：已确认（偏好；成功态最终浏览器视觉未验证）
- 适用条件：原位保存、不需要独立结果页的表单；不限框架版本。
- 现象：成功提示另起一段，与业务正文相似，和触发操作关联不清。
- 检查方法：保存成功及失败后检查反馈真实性、位置、字号和可访问状态；窄屏允许合理换行。
- 通过标准：成功时按钮旁显示简短小号状态，本基线采用绿色“已保存”，不只依靠颜色；失败不显示成功。
- 严重程度与权重：个人基线，不计功能分；反馈真实性按 UI-COMMON-002 检查，不重复计分。
- 原因：源码将成功状态放在表单末尾独立段落。
- 解决办法：按钮和 role=status 文本放入同一可换行容器，应用既有成功色与小字号。
- 来源与日期：用户反馈、源码与自动化，2026-10-05。
- 验证记录：自动化提交后确认“已保存”与按钮共享容器；CSS确认成功色与小字号。浏览器对象已锁定，未为样式验证修改真实配置，成功态实际视觉未验证。

## UI-BASELINE-013 状态清单直接列出具体阻塞原因
- 类型：个人基线
- 状态：已确认（偏好；最终视觉待确认）
- 适用条件：页面已有逐项状态清单，外部系统另返回明确阻塞原因；不限框架版本。
- 现象：清单上方堆叠原因、重试和保留数据等长段说明，当前原因难找。
- 检查方法：对照真实响应，检查原因直接可见，必要恢复操作和启动条件仍可找到；不从状态码臆测原因。
- 通过标准：明确原因成为具名短条目，如“平台返回原因：账号未生效”；删除重复说明但不隐藏决策条件。
- 严重程度与权重：个人基线，不计功能分。
- 原因：已有状态清单上方另渲染重复说明块。
- 解决办法：案例将受控原因映射加入清单，保留逐项状态、恢复入口与启动门禁。通用概念帮助仍参照 UI-BASELINE-002。
- 来源与日期：用户反馈、源码与实测，2026-10-05；原因示例已泛化。
- 验证记录：浏览器初次读取短暂失败，手动核验后显示原因和各项状态；回归确认旧说明块移除。未把首次失败记作成功，最终人工视觉待确认。

## UI-BASELINE-014 多阶段任务分开展示并保留输入
- 类型：个人基线
- 状态：已确认（偏好；最终视觉待确认）
- 适用条件：配置、创建外部对象、准备内容及审核等多阶段任务；不限框架版本。
- 现象：各阶段堆在长弹窗，滚动后难以识别当前任务和下一步。
- 检查方法：切换阶段与方案，检查当前面板；输入草稿后离开再返回；核对导航不触发外部创建或启动。
- 通过标准：当前阶段和方案明确，操作分离，记录仍可访问；切换保留约定草稿，导航不等于提交。
- 严重程度与权重：个人基线，不计功能分；实际丢失输入等故障另按功能规则检查。
- 原因：源码将配置、控制、创建、审核及记录连续渲染。
- 解决办法：案例改为三个独立面板，共享方案选择，隐藏而非卸载配置表单保留草稿，相关记录折叠展示。其他项目可用页面、抽屉或向导，不限定必须弹窗或三步。
- 来源与日期：用户反馈、源码、自动化与实测，2026-10-05。
- 验证记录：浏览器切换三个面板确认内容互斥；自动化验证草稿、共同设置保留及导航无提交。完整键盘路径、窄屏及最终人工视觉未验收。
