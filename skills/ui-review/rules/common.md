# 通用功能基线

以下均为 2026-09-28 建立的初始检查基线，不是用户历史 bug 记录。状态均为已确认（行为标准）；具体项目是否通过必须实际验证。适用于包含相应控件的 UI，不依赖框架版本。历史原因未知、尚无项目修复记录；解决办法由实际失败证据决定。UI-COMMON-003 的滚动遮挡检查点于建立同日经首个实测案例补充（详见 platforms/web.md 的 UI-WEB-001）；UI-COMMON-004 来自 2026-10-02 用户报告并实测修复的案例。

## UI-COMMON-001 选择控件能完成选择
- 类型：功能规则
- 适用条件：存在下拉、单选、多选或同类选择控件。
- 现象：选项不可见/不可点击，或显示值与实际使用值不一致。
- 检查方法：打开控件，选择及变更选项，检查显示与提交/筛选结果；在实际存在的弹窗和滚动容器中重复检查；禁用项不可选。
- 通过标准：选项可见可操作，状态与最终使用值一致，禁用行为符合声明。
- 严重程度与权重：一般 2；阻断关键路径的必填选择时严重 5。

## UI-COMMON-002 操作反馈与真实结果一致
- 类型：功能规则
- 适用条件：存在保存、提交、确认等异步操作。
- 现象：无响应、重复提交、失败却提示成功或丢失输入。
- 检查方法：在安全测试环境执行成功与可控失败路径；观察等待状态、连续触发、失败反馈、重试及真实结果。无法制造失败条件时该测试点未验证。
- 通过标准：反馈与结果一致；进行中的重复操作不会意外重复写入；失败可理解且可恢复，不无故清空输入。
- 严重程度与权重：严重 5。

## UI-COMMON-003 浮层和主要操作可达
- 类型：功能规则
- 适用条件：存在弹窗、菜单、抽屉等浮层。
- 现象：内容被裁剪、主要按钮无法到达、关闭无效或关闭后不能继续操作；或长内容滚动时越过固定标题栏/操作条边界显示。
- 检查方法：在项目支持的窗口/屏幕尺寸下打开浮层，访问长内容及底部操作，把长内容滚动到顶部和底部检查内容被固定标题栏/操作条完全遮挡，按产品允许的方式关闭并继续原页面操作；Web/桌面检查支持的键盘操作及焦点返回。
- 通过标准：内容可读、必要操作可达，固定标题栏/操作条完整遮挡滚动内容；关闭规则符合产品声明，关闭后交互恢复。不可关闭的强制流程不套用普通关闭规则。
- 严重程度与权重：一般 2；主要业务无法继续时严重 5。

## UI-COMMON-004 深色主题的结构性阅读文字不得用低对比灰
- 类型：功能规则
- 状态：已确认
- 适用条件：深色背景 UI 的文字分级体系；不限定框架与平台。
- 现象：表头、时间/状态等元数据列、徽章文字、统计标签使用过深的灰（实测案例约 #6d7f8e 于深海军蓝背景），用户反复反馈看不清；全部改纯白又会丢失信息层次。
- 检查方法：对页面上所有"用户需要读的文字"（表头、元数据列、徽章、按钮、文件列表、内嵌文档表头、日志时间戳、分页条、标签、筛选计数、空态/加载提示）取计算样式颜色，与背景对比；检查次级说明是否只用单一灰档。
- 通过标准：结构性阅读文字用正文亮色（实测案例为 #c8d6e0 类近白）；次级说明文字只用一档亮灰（实测 #8fa5b8 量级）；仅纯装饰（标语、装饰括号、页脚）允许更暗；控件内文字禁止继承暗色。
- 严重程度与权重：一般 2；关键状态信息（失败原因、时间）不可读时严重 5。
- 原因：设计系统灰阶第二档被大量用于实际阅读内容、第三档被用于表头，深背景小字号下对比不足；由用户在同日两次指出后确认。
- 解决办法：三档制并全局梳理：结构性阅读文字归正文色；次级说明归唯一一档亮灰（同时整体调亮灰阶变量，摘要类文本一并受益）；纯装饰归最暗档。已验证范围：单项目（React + CSS 变量设计系统）逐类计算样式核对 + 截图复测；其他项目按检查方法验证。
- 来源与日期：用户报告（同日两次）+ 实测，2026-10-02。
- 验证记录：修改后浏览器逐类取计算样式核对颜色值；截图确认可读性与层次保留（彩色徽章不受影响、摘要保持次级灰）。
