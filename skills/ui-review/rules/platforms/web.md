# Web 平台规则

UI-WEB-001 至 UI-WEB-005 来自用户报告并实测修复的案例（2026-09-28、2026-10-02），解决办法未逐一覆盖全部浏览器。后续条目的用户报告、源码证据、自动化检查与真实浏览器验证分别列出，不将其中一类证据替代另一类。规则不限前端框架，具体项目是否通过必须按适用条件实际验证。

## UI-WEB-001 可滚动浮层的固定标题栏必须完全遮挡滚动内容
- 类型：功能规则
- 状态：已确认
- 适用条件：Web 浮层（原生 dialog 或 div 弹层）内容超出高度限制形成内部滚动，标题栏或底部操作条用 position: sticky 固定并承担遮挡职责。
- 现象：滚动浮层长内容时，正文（如首行表单标签）显示到标题栏上方或周边未被遮挡的区域，标题栏看似"透明"；底部 sticky 操作条同理，内容从其下方或周边穿透。
- 检查方法：将长内容浮层分别滚动到顶部、中部、底部，检查滚动内容是否被 sticky 标题栏与操作条完全遮挡；可辅以几何断言（标题栏与浮层可视区顶边间隙应为 0）。抽查多个内部结构不同的弹窗（内容有包装层与表单控件直接作为弹窗子元素两种）。
- 通过标准：任意滚动位置下，sticky 标题栏与操作条背景不透明、完整遮挡其后滚动的内容，与浮层可视区顶/底边无间隙。
- 严重程度与权重：一般 2；遮挡导致关键信息误读或操作条不可用时严重 5。
- 原因：sticky 元素受其包含块（滚动容器的内容盒）约束，不能越过包含块顶边；滚动容器上下方向有 padding 时，包含块顶边位于 padding 之后，sticky 标题栏最多停到 padding 结束处、贴不到滚动区顶端，内容从 padding 条带穿透显示（overflow 裁剪只到 padding box 边缘）。已确认：CSS 定位机制 + Chromium 修复前后复现。
- 解决办法：滚动容器上下方向 padding 归零（左右可保留），首尾留白由首/末内容元素自身的 padding 或 margin 提供；遮挡交给自带不透明背景与内边距的 sticky 标题栏/操作条；末尾有 sticky 操作条时，给末尾元素补留白的规则需排除该操作条，避免把它推离底边。已验证范围：单项目 Chromium 隔离复现页修复前后对比 + 真实浏览器复测；其他浏览器未逐一验证。
- 来源与日期：用户报告 + 实测，2026-09-28。
- 验证记录：修复前隔离复现页稳定复现顶部穿透；修复后顶部、底部均无穿透（覆盖两种弹窗内部结构与底部 sticky 操作条）；真实应用两个长内容弹窗滚动复测，标题栏与浮层顶边间隙为 0。

## UI-WEB-002 CJK 短文本表格列不得被逐字折行，长文本列负责吸收宽度
- 类型：功能规则
- 状态：已确认
- 适用条件：HTML 表格（auto 布局）中含中文等 CJK 文本的短元数据列（状态词、标记、时间戳）；不限定前端框架，判断的是表格布局机制。
- 现象：列宽不足时两字状态词被折成一字一行；整串时间戳在任意字符间乱断；给短列加 white-space: nowrap 后，窄视口下各列最小宽度累计超出容器，表格整体溢出父卡片。
- 检查方法：在受支持的窄视口（如 1100-1200px 桌面窗口）逐列检查短元数据单元格是否单行；测量表格宽度是否超出父容器；确认长文本列（标题/说明/摘要）在正常换行吸收剩余宽度。
- 通过标准：徽章、按钮、短状态词、时间在任意受支持视口下单行；表格不溢出容器；剩余宽度由长文本列吸收。
- 严重程度与权重：一般 2；时间/状态被误读影响决策时严重 5。
- 原因：CJK 文本任意字符间都是合法断点，浏览器计算列最小宽度时短词只按一个字计，空间不足时短列最先被压缩折行（英文单词无词间断点不受影响）；nowrap 使列最小宽度等于全文宽度，多列累计超过容器。
- 解决办法：三层组合：① 徽章与按钮全局 white-space: nowrap；② 纯文本短单元格加 nowrap 工具类；③ 时间戳用受控两行组件（日期一行、时间一行），列宽稳定且避免 nowrap 累计溢出；长文本列不加 nowrap。禁止整串时间戳依赖浏览器自动换行，也禁止只靠 nowrap 硬撑。
- 来源与日期：用户报告（多轮逐列指出）+ 实测，2026-10-02。
- 验证记录：1200px 视口计算样式核对短列单行、表格不溢出；1100px 验证两行时间组件稳定；截图确认。

## UI-WEB-003 内容受限时不得在容器两侧保留大量留白
- 类型：功能规则
- 状态：已确认
- 适用条件：列表/表格类主内容区设有 max-width 上限、或长文本列设有 maxWidth 限制的 Web 页面。
- 现象：主内容区设约 1240px 上限并居中，宽屏（≥1400px）左右各留大块空隙；同时说明/摘要列被固定 maxWidth（实测 380/320px）限制被迫多行截断——空间紧张与空间浪费同时存在。
- 检查方法：在宽视口测量主内容区两侧空隙与长文本列实际宽度；确认长文本列是否先占满可用宽度再换行。
- 通过标准：内容优先占满：主内容区不设（或足够大的）max-width；表格 width: 100%；长文本弹性列不限 maxWidth，多余空间全部让给内容，确有剩余才留白。
- 严重程度与权重：一般 2。
- 原因：居中容器上限按常规阅读宽度设计，与数据密集列表页的宽度需求冲突；列级 maxWidth 沿用固定值未随布局调整。
- 解决办法：删除主内容区 max-width 与居中；删除长文本列固定 maxWidth；表头加 nowrap 让列宽按内容自适应（配合 UI-WEB-002）。已验证范围：单项目宽/窄视口实测；超宽屏（>2000px）行阅读性未评估，需要时再设上限。
- 来源与日期：用户报告 + 实测，2026-10-02。
- 验证记录：1600px 视口实测内容区铺满至视口内边距，弹性列宽度由 380px 增至约 557px。

## UI-WEB-004 应用式 Web UI 的固定骨架区禁选禁拖
- 类型：功能规则
- 状态：已确认
- 适用条件：以应用形态使用（非文档阅读为主）的 Web UI，含侧边栏导航、工具栏、分页条等固定骨架区；内容区除外。
- 现象：侧边栏导航文字可被双击选中高亮、导航链接可被按住拖拽（浏览器默认把链接拖成 URL），操作手感差。
- 检查方法：在骨架区双击文字观察是否出现选区；按住导航链接拖动观察是否出现拖拽行为；对照内容区文字仍可正常选中复制。
- 通过标准：骨架区双击无选区、拖动无效；内容区（表格文字、摘要、代码）保持可选可复制。
- 严重程度与权重：轻微 1。
- 原因：浏览器默认允许选中文本与拖动链接，应用式 UI 未覆盖默认行为。
- 解决办法：骨架区容器 user-select: none（含 -webkit 前缀），区内链接 -webkit-user-drag: none；内容区不加。
- 来源与日期：用户报告 + 实测，2026-10-02。
- 验证记录：双击骨架导航无选区、双击内容区可选中（getSelection 对照）；计算样式核对两条属性均生效。

## UI-WEB-005 列表分页条位置不得随行数与换行差异漂移
- 类型：功能规则
- 状态：已确认
- 适用条件：分页数据列表（表格或卡片流），分页条位于内容下方；不限定前端框架，判断的是文档流布局稳定性机制。
- 现象：翻到行数不足整页的末页、或筛选后行数变少时，内容区变矮、分页条整体上浮；行内文本换行多少不同还让整页与整页之间高度不一致——连续翻页时分页条上下漂移，没有稳定的位置和点击目标。
- 检查方法：翻到每个分页（重点末页）并改变筛选，测量分页条纵坐标（如 getBoundingClientRect().top）比较差值；构造同列表"长文本多换行页"与"短文本页"对照；检查不足一页（无分页条）的列表是否被撑出大块空白。
- 通过标准：同一列表任意页/筛选状态下分页条位置一致（实测残差 5px 量级以内）；列表不足一页、分页条本就不显示时不做占位，不出现大空卡片。
- 严重程度与权重：一般 2。
- 原因：内容高度天然随行数与换行变化，分页条跟随文档流移动。已确认两种错误修法：① 按本页最后一行实测行高补占位行——整页之间行高仍有换行差异，末页依旧偏低；② 把整页高度记在组件 state 里——翻页时数据重新加载、表格被加载态替换导致占位组件卸载重挂，记忆清零、占位高度归零（React Query 翻页实测复现）。
- 解决办法：占位行补到"整页基准高度"：① 基准存模块级缓存，按「路由 + 每页条数」分键，组件卸载不丢，窗口 resize 时清空重测；② 仅当本页真实行数 ≥ 每页条数时刷新基准（取历史最大值）；③ 任何页（含整页）内容高度低于基准时，用单根弹性占位行补差值，占位行去掉内边距与边框、不响应悬停，视觉上不可见；④ 展开行等附加行不计入基准，避免用户主动展开详情把基准撑高；⑤ 测量与设高放 useLayoutEffect，绘制前完成二次渲染，避免占位高度先大后小的闪烁；⑥ 无分页条时渲染空占位（高度 0），不参与布局。已验证范围：单项目（React）三个列表页实测；其他框架按检查方法验证。
- 来源与日期：用户报告（明确要求"就算没有整页行数，也要固定在整页那个位置不变"）+ 实测，2026-10-02。
- 验证记录：三个列表页翻首/中/末页再返回，分页条纵坐标差 ≤5px（修复前同操作漂移约 400px）；末页截图确认占位区域无边框残留、底部干净。

## UI-WEB-006 分批追加列表须在当前查询内有界加载且保持数据一致
- 类型：功能规则
- 状态：已确认（行为标准；案例触底视觉交互尚未完整复验）
- 适用条件：产品明确选择触底追加、接口能确定当前数据范围的 Web 列表；不限定框架版本，因为涉及请求并发、查询上下文与终止条件。本例为 React 18 的手机只读榜单；不要求分页列表一律改成触底追加。
- 现象：用户报告有限榜单的翻页、跳页和条数控件过于复杂，空榜仍出现控制条，随后明确要求分批追加。重复追加、旧查询响应串入新列表等是切换交互时必须防止的回归风险，不作为已经实测发生的历史故障。
- 检查方法：连续触底、同批重复触发；加载中切换对象或 Tab、离开并返回；构造追加失败后重试、重复条目、数据快照变化；检查空列表、短末批、全部读完及明确上限。分别验证请求参数、返回顺序、可见条目与实际滚动容器的哨兵行为。
- 通过标准：同批最多一个有效在途请求，条目按稳定身份去重并保持来源顺序；切换查询后旧响应不能追加到新列表；失败保留已读内容并允许明确重试，不能因哨兵可见无限重试。数据已读完、空榜或达到约定上限时停止追加，不保留无效分页或加载占位；不同快照不得混合。
- 严重程度与权重：一般 2；具体项目若因串数据造成更严重影响，在检查前另行说明严重级别。
- 原因：此次交互变更由用户明确提出；源码显示旧界面按页码和分页栏组织，新的查询上下文、并发锁和快照一致性均需显式维护。没有证据证明旧代码实际出现过所有列举的竞态风险。
- 解决办法：案例固定每批读取 20 条已保存数据、最多展示 100 条；使用当前查询上下文与请求代次校验、同步在途锁、稳定 ID 去重和停止条件；追加失败停在原批次等待重试，快照变化时清空并有界重读。IntersectionObserver 的 root 指向实际内容滚动区，切换查询清理旧观察器。批量大小及总上限是本例合同，不是通用规定；普通页码列表继续适用原分页规则。
- 来源与日期：用户截图报告、明确交互要求、源码检查及离线自动化，2026-10-05。
- 验证记录：相关 hook 52 项及视图 13 项回归通过；已有只读本地接口验收记录为五批各 20 条、100 个唯一条目，空难度为零条，不代表真实厂商调用。用户后续认可榜单布局，但未逐项复验上述所有交互；真实浏览器触底触发、快速切换及布局测量仍未验证，不以测试或构建替代。

## UI-WEB-007 手机应用骨架不得重复预留底栏与安全区空间
- 类型：功能规则
- 状态：已确认（行为标准；案例最终尺寸测量未完成）
- 适用条件：手机 Web 应用外层按视口布局，底部导航已经独占布局空间，内部页面仍可能使用整屏最小高度或底部避让；不限定框架版本，问题来自 CSS 尺寸和空间归属。
- 现象：用户滚到列表末尾后还能继续滑动一大块空白；空列表时旧控制栏浮到中间。后者的控件存在性按 UI-WEB-006 的空态条件检查，本条只评价重复空间，避免对同一问题重复计分。
- 检查方法：确认实际滚动容器与底栏是否在文档流中；逐层检查 min-height、height、底部 padding/margin 和 safe-area。对长列表末尾、短内容、空态逐一测量，检查最后一项可见且没有重复的导航高度留白。
- 通过标准：内容只按真正可用高度布局，底栏及安全区各有明确的一处空间责任；长内容末尾仅保留设计约定的间距，短内容可以保留正常剩余视口但不因叠加高度产生额外滚动。固定覆盖式底栏仍须保留必要避让，不可为消灭留白而遮挡内容。
- 严重程度与权重：一般 2。
- 原因：源码确认，外层底栏已占独立 flex 行，内层页面仍按 100vh 最小高度和额外底栏 padding 计算，重复预留同一块空间；末尾区块外边距又继续叠加。
- 解决办法：案例将页面最小高度约束到实际内容区，删除该骨架内多余的底栏占位，安全区由底部导航单独承担；外层优先使用动态视口高度并保留旧浏览器回退。只对适用骨架覆盖共享组件规则，不全局删除其他布局仍需要的底部避让。
- 来源与日期：用户报告列表末尾空白、提供空态截图，源码检查，2026-10-05。
- 验证记录：相关布局已修改，客户端边界检查、测试及构建通过；用户后续继续验收该列表，但没有覆盖所有空态、软键盘或多浏览器几何测量的证据。上述运行尺寸仍标未验证，不将源码修复表述为所有设备已通过。
