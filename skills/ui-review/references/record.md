# 记录与成长

## 定位源码

按顺序寻找：用户本次指定的仓库 → 本机环境变量 UI_REVIEW_REPO → 当前工作区或已知本机仓库中 remote 指向 czm233/my-codex-skills 的 Git 根目录。验证其中 skills/ui-review/SKILL.md 的 name 为 ui-review，并读取仓库 AGENTS.md。不要遍历整个磁盘或把安装缓存误认为源码。

本机路径可由用户在本地配置；不把特定用户名或机器绝对路径写入共享 skill。找不到维护仓库时，先在回复中整理待写入内容，再询问仓库位置，不退回写安装副本。只做检查的设备无需维护仓库。

写入前检查 Git 状态和已有内容，保留无关改动；存在同一规则未完成修改或冲突时先澄清。不要自动 pull 覆盖工作区。

## 提炼并去重

从刚才的对话、实际差异、复现和复测结果提取：技术及版本、触发条件、现象、已确认原因、解决办法、验证证据。缺少对话上下文时询问问题与修复，不虚构刚才发生过什么。

先在源码 rules/index.md 及相关规则中检索现象、组件、根因、ID：同类问题补充既有规则；已有规则范围或办法失效则修订；不同检查目标才新增 ID。跨框架问题放通用或平台规则，不在 React/Vue 中重复复制。

用户明确报告发生的现象可记为用户报告，但原因/修复未经证实须标未确认。可以执行的行为标准与尚待验证的修复方法分别标记。无法建立可靠检查标准的案例设为待确认，不参与评分。网上资料只作外部候选，核对适用版本与一手来源后再采用，不冒充个人经历。

纯审美意见不进入功能规则；明确可执行的个人偏好进入个人基线。不把单次修复方案提升为所有项目的唯一实现。新增文件时同步索引，只创建有实际内容的分类。

## 规则格式

每个检查目标一个稳定 ID；废弃 ID 不再复用。

```markdown
## UI-类别-编号 简短行为标准
- 类型：功能规则 / 个人基线
- 状态：已确认 / 待确认 / 废弃
- 适用条件：平台、框架、版本和必要场景；不限定版本须有理由
- 现象：可观察的错误
- 检查方法：可以执行的操作或源码检查
- 通过标准：明确的预期结果
- 严重程度与权重：严重 5 / 一般 2 / 轻微 1；基线不计功能分
- 原因：已确认事实；未知则写未知
- 解决办法：已验证办法及范围；未验证则明确标注
- 来源与日期：用户报告 / 实测 / 外部资料 / 初始检查基线，日期及可公开引用
- 验证记录：如何确认修复；无证据写未验证
```

先写可迁移的经验，项目名称、内部 URL、账号、真实数据、凭证和本机路径不得进入公开案例。保留必要版本信息；大段对话、日志和截图不复制进公共规则库。

## 敏感信息脱敏

- 记录前先脱敏，禁止把真实 API Key、Token、密码、私钥、Cookie、Authorization 请求头、会话标识、数据库连接凭证、Webhook Secret、OAuth Secret 或带签名/鉴权参数的 URL 写入规则、案例、草稿、报告、命令示例、日志和审查差异。
- 保留说明问题所需的字段名和结构，将敏感值整体替换为 `<REDACTED_API_KEY>`、`<REDACTED_TOKEN>`、`<REDACTED_PASSWORD>` 等明确占位值；不保留真实值的前后缀，也不通过编码或可逆转换保存原值。账号和其他个人信息同样使用虚构占位值。
- 从对话、配置、请求响应或截图提炼经验时，不直接复制原文或原图。截图无法可靠脱敏时不保存，改写为脱敏文字。示例只使用空值、假值或明确占位值。
- 写入前及展示差异前都检查敏感内容；不确定某个值是否敏感时按敏感信息处理。检查结果只报告字段类型与位置，不输出命中的原值。若原文件已有敏感值，不展示含原值的原始 diff，用脱敏摘要说明修改。
- 如果发现真实凭证已被记录或进入 Git 历史，停止传播，提醒用户作废并轮换；清理当前文档不能视为历史凭证已安全，不自动改写 Git 历史或推送。

## 完成

检查重复 ID、索引链接、状态和字段完整性。展示新增/修订 ID、提炼内容、证据不足项与源码位置。按仓库约定同步安装版本前比较差异，遇到独立本机修改不覆盖。完成后停止在本地未提交状态，展示实际差异供用户审查，并明确报告“已记录到本地，未提交、未推送；请审查后手动推送”。记录模式不得执行 git add、git commit、git push，不创建 PR，不调用 GitHub API 或其他发布渠道代替推送，也不安排后续自动发布。即使仓库一般约定允许自动推送，UI 记录仍适用本条人工发布例外。用户说“记录”“继续”“完成”或确认内容，不触发发布；用户自行执行推送。源码修改与本机同步状态分别如实报告。
